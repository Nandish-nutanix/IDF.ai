The pipeline at a glance

How it works — and how it was built

Four steps turn a plain-English question into a valid IDF query proto. Nothing is guessed — every entity and field is checked against your cluster's real schema before it reaches you.

1

Ground in the schema

We read the question and pull the matching entity type, its valid fields, and a few real examples straight from the live IDF schema.

2

Phi-4 drafts the query

Microsoft Phi-4 (running locally on Apple Silicon via MLX) writes a candidate query proto using only the grounded context.

3

Validate & repair

Every entity, field, and type is checked against the real schema. Wrong or invalid fields are corrected automatically.

4

Render a valid proto

A deterministic renderer emits syntactically correct proto text — plus the runnable Python and a confidence score.

Trained on truth

Real-schema data

Training examples are generated from the actual IDF schema, so the model learns your entities and fields — not a generic guess.

Fine-tuned

LoRA + GRPO

Phi-4 is fine-tuned with LoRA, then reward-tuned with GRPO on a schema-aware reward (right format, right API, valid fields, matches intent).

Never fails

Constrained + fallback

Grammar-constrained decoding keeps output structurally valid; if a draft still can't be fixed, a guaranteed minimal proto is returned.

The result: every query returns a valid, schema-faithful proto — grounded in your real schema, validated field-by-field, and safe to run against the cluster.
