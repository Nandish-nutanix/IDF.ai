Create — Register a VM Entity in IDF UpdateEntity (Create)
The first step in any VM lifecycle is registering it in IDF. In IDF, creation and update use the same API — UpdateEntity. If the entity doesn't exist yet, it gets created. You provide the entity type, a unique ID (UUID), and the initial attributes.

What to edit here

entity_id → Replace "abc123-vm-uuid-placeholder" with any UUID you want to assign to this new VM.
attribute_data_arg_list → Each block sets one attribute. Change vm_name, power_state, num_vcpus, memory_size_bytes values to whatever you want.
Adding attributes → Copy any attribute_data_arg_list { ... } block and change the name/value to add more fields.

Read — Query the VM Entity Back GetEntitiesWithMetrics
After creating the VM, let's read it back from IDF to confirm it was stored. This uses GetEntitiesWithMetrics — the primary read API. We query for VMs and select the columns we want returned.

What to edit here

entity_type_name → Currently "vm". This is the entity type to query.
raw_columns → Each { column: "..." } selects an attribute to return. Add or remove columns as needed.
where_clause → Filters results. Match by vm_name equals "test-vm-workflow-01".
raw_limit → Controls max results. Change limit: 10 to any number.

Register Entity Type — Schema with Replication Config RegisterEntityTypes
Register the entity type with its attributes and replication config. The key flag is suppress_replication: false — this tells IDF that entities of this type should replicate from PE to PC via the sync framework.

What to edit here

entity_type_name → The entity type to register. Replace "idf_workflow_sync_test" with your type.
metric_type_list → Attributes to register. Add more by duplicating blocks.
suppress_replication → Must be false for sync to work. If true, entity never replicates.

Register Watch Client — Establish a Session RegisterWatchClient
Before registering any watches, you must establish a watch client session. This pairs a client_id (your component name) with a unique session_id (UUID). The combination must be globally unique across the cluster.

What to edit here

client_id → Your service name, e.g. "my_service", "acropolis", or "prism_central".
session_id → A unique UUID for this session. Generate a new one per connection.
reset_watch_client_on_operations → Bitwise flag: 0 = kNoReset (default). Set to 1 to reset on errors.

RegisterWatchClient — Start Session

Register Watch — Subscribe to VM Creation Events RegisterWatch
Now define what to watch for. A watch specifies an entity type, the operation type (create/update/delete), and an optional filter condition. Here we watch for any new VM entity being created.

What to edit here

watch_name → Unique name: "NewVMCreation". Must be unique per client_id.
entity_type_name → Entity type to watch: "vm".
entity_watch_type → Bitwise: 1=Create, 2=Update, 4=Delete, 6=Update|Delete, 7=All.
get_current_state → If true, returns existing entities immediately (may be verbose). Set to false for only new events.

Poll Fired Watches — Long-Poll for Changes GetFiredWatchList
This is the event loop. GetFiredWatchList blocks (long-polls) until either a watched event fires or the timeout expires. Each response includes a sequence_id — pass it back in the next call to only get new events.

What to edit here

client_id / session_id → Must match your registered client from Step 1.
rpc_timeout_in_secs → How long to wait (seconds). Default 3 for quick testing. Increase for real use.
fired_watch_last_sequence_num → Start at 0 for first call. Use the returned sequence_id for subsequent calls.
